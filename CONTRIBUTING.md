# Contributing to Awesome Agent Harnesses

Thank you for your interest in contributing! This project aims to maintain the most comprehensive, accurately-linked, and up-to-date collection of research and engineering on **agent harnesses** — the code, configuration, and execution logic wrapped around a foundation model (Agent = Model + Harness). The agent loop is the harness's core mechanism; tools, memory, context, planning, runtime, and safety are its other components.

## How to Contribute

### Adding a New Entry

A paper qualifies if the **harness or loop is a first-class contribution** — e.g. a new agent-computer interface, scaffold, runtime, context/memory architecture, planning/search loop, multi-agent harness, or a benchmark/study that directly evaluates harness design. Papers that *use* an agent to solve a downstream task (without harness/loop novelty) are out of scope.

For each entry provide:

- **Title** — exact, matching the arXiv page.
- **arXiv ID** — `YYMM.NNNNN`, verified to resolve.
- **GitHub** — the *official* repo link. If the arXiv abstract page has none, **check the paper's PDF body** — many projects only disclose their code link inside the paper. Use `/` only if no public code exists.
- **Year / Venue** — e.g. `NeurIPS 24`, `ICLR 25`, `arXiv`.
- **Keywords** — 2–4 short tags.

For blogs/talks/tools: long-form content only (no one-line tweets). Give the canonical URL.

### Verification Bar

Every link must be **live**:

- arXiv IDs: must resolve on arxiv.org/abs/`<id>`.
- GitHub URLs: must return HTTP 200 (follow redirects).
- Web URLs: must resolve and the title/author must match.

Fabricated or dead links will be rejected. If you are unsure of an ID, leave it out rather than guess.

### Submission Format

Open a PR editing `README.md` inside the appropriate section table, sorted by year then title. Add a one-line rationale in the PR description for why it belongs in *this* list (vs. a generic agent-awesome-list).
